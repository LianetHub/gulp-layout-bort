# Проверка интерфейса

`npm run format` форматирует самописный JS/SCSS через Prettier и HTML из `src` через js-beautify; `npm run format:check` проверяет результат без записи. Настройки HTML находятся в `.jsbeautifyrc` и согласованы с `.vscode/settings.json`. Директивы `@@for` сохраняются целиком, чтобы сравнения JavaScript не влияли на разбор HTML; подключаемые ими шаблоны форматируются отдельно.

`tests/markup-refactor.test.js` проверяет раскрытые страницы: отсутствие Row/Col, интерфейсных SVG и пустых `alt`. Сохраняемая SVG-графика перечислена явно. `tests/html-format.test.js` проверяет директивы, пробелы, идемпотентность форматирования и загрузку Gulp CLI. В `npm run test:browser` включена проверка шрифтовых иконок, формы заказа и добавления товара на ширинах 375 и 1440px.

`npm test` запускает тесты логики, метрик иконочного шрифта, отсутствия сохранения состояния и целостности HTML-шаблонов.

После рефакторинга весь самописный браузерный код находится в `src/js/app.js`. Разделы отмечены комментариями; общая замкнутая область видимости не добавляет глобальных переменных. Gulp копирует файл без изменений в `docs/js/app.js` в обоих режимах сборки. Swiper и Fancybox подключаются отдельно. Для изменения select внутри этого файла доступны `CustomSelect.get(element).refresh()` и стандартные события `change`.

Статическая разметка, ошибки валидации форм, данные товаров, контакты и ПВЗ остаются в HTML и JSON компонентов. Динамические сообщения, подписи состояний и форматирование текущих значений находятся в соответствующих обработчиках `src/js/app.js`. Фрагменты пагинации создаются в функциях Swiper. Общего HTML-хранилища строк нет.

Данные ПВЗ читаются из `.pickup-dialog__point` (атрибуты и подписанные дочерние элементы); источник наполнения при сборке — существующий JSON каталога. Координаты карты хранятся в `data-map-center`, значок — в `data-map-marker`. Номер заказа берётся из `[data-order-number]`; сообщения страницы заказа заранее находятся в HTML и переключаются через `hidden` по `data-order-state`. Контакты редактируются в этих HTML-состояниях.

Перетаскивание `.comparing__desc` управляет существующими Swiper: на настольном экране — общим, на мобильном — колонкой в соответствующей половине области. Кнопки, ссылки и поля исключены из зоны начала жеста; вертикальная прокрутка сохраняется через `touch-action: pan-y`. Характеристики синхронизируют переход с карточками; reduced motion отключает их анимацию. `tests/browser/html-content.spec.js` дополнительно проверяет реальные touch-события, переключение колонок, редактирование HTML и копирование номера заказа.

Команды проверки (Node.js 22+):

- `npm run validate:html` — раскрыть все 24 страницы в памяти и проверить HTML, подписи полей, ссылки ARIA и обязательный по правилам проекта `action` форм. Координаты ошибок относятся к раскрытой странице. Для локальных ресурсов SRI не требуется; правило остаётся включённым для внешних ресурсов.
- `npm test` — тесты логики и валидации; браузерный файл проверяется через `node:vm`, без экспортов в production.
- `npm run test:browser` — Playwright с установленным Google Chrome; сервер на `127.0.0.1:4176` запускается автоматически. Перед запуском собрать HTML и JS: `node node_modules/gulp/bin/gulp.js html js --build`. Команда не очищает `docs`.
- `npm run format:check` — проверка оформления JavaScript и SCSS.

Браузерные проверки охватывают все страницы на 375 и 1440px, существующие стенды интерфейса, динамическую HTML-разметку, отсутствие библиотек, добавление адреса, повторную инициализацию товара/галерей, сброс ошибок форм и вставку целого номера или отдельных цифр телефона. В проверке динамического HTML запрос Яндекс.Карт блокируется: проверяется собственный fallback, а не сторонняя разметка карты. Реальный ответ Яндекс.Карт и серверная обработка форм требуют отдельной интеграционной проверки после подключения сервисов.

Старый адрес `tests/browser.html` запускает актуальный стенд `demo-browser.js`: прежние сценарии зависели в том числе от уже отсутствовавших range/catalog/auth-модулей. Отдельный стенд `tests/checkout.html` использует тестовый загрузчик единого приложения. В карточке с единственной фотографией проверяется статическое изображение; многокадровые галереи проверяются отдельной фикстурой с несколькими фотографиями.

Исправлены пропуск отключённых обязательных полей и проверка radio-групп, очистка ошибок при reset, вставка номера с сохранением невыделенных цифр, повторная загрузка карты после таймаута, дублирование загрузчиков карты и повторных обработчиков товара. Повторный запуск слайдеров сохраняет активную миниатюру. В разметке исправлены action, подписи полей, роли именованных групп/диалогов, заголовки, autocomplete и размеры изображений; элементы управления select вынесены из label.

`tests/ui-unification.html` проверяет темы, заголовки, промокарточки, локальную навигацию Swiper, адаптивность FAQ и policy на ширинах 375, 768, 1199, 1200 и 1440px; отдельно проверяет нативное раскрытие FAQ без JavaScript. После сборки открыть через HTTP-сервер из корня проекта. `tests/ui-stage-two.html` проверяет общие компоненты, включая анимацию FAQ и reduced motion.

Для браузерной проверки:

1. Собрать проект: `npm run build` (сборка не очищает `docs`).
2. Из корня запустить `python -m http.server 4174 --bind 127.0.0.1`.
3. Открыть `http://127.0.0.1:4174/tests/demo.html`.
4. Дождаться заголовка `PASS: 78 проверок интерфейса`.

Проверяются ширины 1440px и 375px: избранное, вложенные Swiper-галереи, свайпы, пагинация, рекомендации корзины, сравнение и скрытые колонки, пароли, авторизация, адреса и пункты выдачи. Для отдельной ширины доступен параметр `?width=375`.

Тестовый стенд загружает собранные страницы в iframe с `srcdoc` и базовым URL `docs/`, сохраняя загрузку настоящих CSS, JavaScript и изображений. Отправка заказа и запросы кодов авторизации не выполняются.

Второй этап общих UI-правок проверяется на `http://127.0.0.1:4174/tests/ui-stage-two.html`.
Ожидаемый результат — `PASS: 192 проверок второго этапа` на ширинах 375, 768 и 1440 px.
Проверки включают единый сайдбар, статическую выдачу, оба состояния кнопок, быстрые клики FAQ и reduced motion, повторяющиеся имена файлов, удаление из FileList/FormData и reset всех загрузчиков.

UI-кит проверяется на `http://127.0.0.1:4174/tests/ui-kit.html`.
Ожидаемый результат — `PASS: 110 проверок UI-кита`: поиск и мультивыбор select, FormData, клавиатура и click, disabled, валидация и reset, очистка чипов, цвета и размеры кнопок, focus/error полей, tooltip, файлы и три вида уведомлений. Реальные страницы проверяются на 375, 768 и 1440px, включая смену брейкпоинта с открытым каталогом и fallback select без JavaScript.

Подключение select: `data-custom-select`; поиск по вариантам: `data-has-search`; множественный выбор: `multiple`; представление очищаемым чипом: `data-select-chip` вместе с `aria-label`. Нативный select хранит значения и участвует в FormData. Программные изменения выполняются стандартными value/change; внутренние функции компонента находятся в разделе select единого `app.js`.

Общий шаблон бейджа: `html/templates/_badge.html` с параметрами `color` (`orange`, `yellow`, `green`), `icon` (имя существующего глифа без `icon-`) и `text`. Уведомления: `window.NotifyController.show(name, quantity, type)`, где type — `cart`, `favorite`, `compare`. Tooltip использует HTML-текст внутри `.tooltip__content > .tooltip__text`; триггер связывается с ним через `aria-describedby`.
